## 3. Policy B Implementation (Similarity-Based Retrieval)

- **Implementation:** [`CandidateSelector.select_similarity()`](file:///C:/Users/swarsh/Desktop/autodba-research/research/candidate_selector.py)
- **Selection Logic:**
  - Computes deterministic token-hash vector cosine similarity $\text{sim}(Q_{\text{test}}, h.\text{query})$ against each historical case $h \in \mathcal{H}_{\text{train}}$ from the leakage-safe `TRAIN` partition.
  - Matches historical cases to candidates in $\mathcal{C}_{\text{candidates}}$ via canonical key $\kappa(h) == \kappa(c)$.
  - Aggregates similarity support $S_{\text{sim}}(c) = \sum_{h \in \mathcal{H}_{\text{train}} \mid \kappa(h) = \kappa(c)} \text{sim}(Q_{\text{test}}, h)$.
  - Scores candidates by $\text{Score}_B(c) = C_{\text{hypo}}(c) + \alpha \cdot S_{\text{sim}}(c)$.
  - Does **not** use historical success/regression outcome values.
  - **Boundary:** Can **never** select or create candidates outside the Phase 1 candidate pool.
  - **Deterministic Tie-Breaking:** (1) Highest composite score, (2) Highest HypoPG cost improvement, (3) `is_baseline == True`, (4) Lexicographical candidate ID.

## 4. Policy C Implementation (Outcome-Aware Selection)

- **Implementation:** [`CandidateSelector.select_outcome_aware()`](file:///C:/Users/swarsh/Desktop/autodba-research/research/candidate_selector.py)
- **Selection Logic:**
  - Filters `TRAIN` history strictly to **eligible verified measured cases** satisfying:
    $$\text{provenance} == \text{MEASURED} \;\land\; \text{is\_verified} == \text{True} \;\land\; \text{verification\_state} == \text{VERIFIED\_MEASURED}$$
  - Unverified, seeded, or synthetic cases are excluded ($\omega = 0$).
  - For each eligible historical case $h$ matching candidate $c$ via $\kappa(h) == \kappa(c)$, calculates relative runtime delta $\Delta_{\text{runtime}}(h)$ and weights it by query similarity $\text{sim}(Q_{\text{test}}, h.\text{query})$ and regression penalty $\lambda_{\text{reg}}$.
  - Scores candidates by $\text{Score}_C(c) = C_{\text{hypo}}(c) + \beta \cdot S_{\text{outcome}}(c)$.
  - **Boundary:** Operates strictly within the Phase 1 candidate pool.

---

## 5. Candidate Matching Rule

Matching between a candidate recommendation $c$ and a historical case $h$ is defined by the canonical tuple:

$$\kappa = \left( \text{table.strip().lower()}, \; \text{index\_method.strip().lower()}, \; \text{tuple}(col\text{.strip().lower() for } col \in \text{columns}) \right)$$

- **Scope:** Scoped strictly to standard single-column and multi-column B-tree secondary index recommendations generated by AutoDBA.
- **Prefix Ordering:** Preserves exact column ordering for B-tree index semantics.
- Partial indexes, expression indexes, and included columns are not generated by AutoDBA and are explicitly excluded from the research scope.

---

## 6. Outcome Calculation

For an eligible measured historical case $h$:

$$\Delta_{\text{runtime}}(h) = \frac{T_{\text{before}} - T_{\text{after}}}{T_{\text{before}}}$$

- $T_{\text{before}}$ and $T_{\text{after}}$ represent arithmetic mean execution times across measured runs (`ExecutionMeasurement.mean_execution_time_ms`).
- $\Delta_{\text{runtime}} > 0$: Improvement ($T_{\text{after}} < T_{\text{before}}$).
- $\Delta_{\text{runtime}} = 0$: No change.
- $\Delta_{\text{runtime}} < 0$: Performance regression ($T_{\text{after}} > T_{\text{before}}$).
- If $T_{\text{before}} \le 0$ or values are missing, the measurement is treated as invalid and excluded from outcome aggregation.

---

## 7. Regression Penalty ($\lambda_{\text{reg}}$)

- The regression penalty $\lambda_{\text{reg}}$ is an experimental hyperparameter representing risk aversion against regressions:
  $$\text{contribution}(h) = \begin{cases}
  \text{sim} \cdot \Delta_{\text{runtime}}(h) & \text{if } \Delta_{\text{runtime}}(h) \ge 0 \\
  \text{sim} \cdot \Delta_{\text{runtime}}(h) \cdot \lambda_{\text{reg}} & \text{if } \Delta_{\text{runtime}}(h) < 0
  \end{cases}$$
- Default experimental setting: $\lambda_{\text{reg}} = 1.0$ (symmetric).
- Evaluated across experimental settings ($\lambda_{\text{reg}} \ge 1.0$).
- **Hyperparameter Rule:** Calibration of $\lambda_{\text{reg}}$ must occur **strictly on training/development splits**. The held-out `TEST` partition must never be used to tune $\lambda_{\text{reg}}$.

---

## 8. Fallback Behavior

When no eligible verified measured historical cases match a candidate in the training corpus:
- Historical outcome support evaluates to 0: $S_{\text{outcome}}(c) = 0.0$.
- Policy C sets `fallback_used = True`, records `fallback_reason`, and selects the candidate chosen by Policy A.
- **Scientifically Defensible Statement:**
  > *"When no eligible measured historical evidence exists, the outcome-aware selection policy falls back to the planner-only baseline selection. This defines a deterministic no-history fallback, but does not guarantee a non-regressive physical benchmark outcome."*
